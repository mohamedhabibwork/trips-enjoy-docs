# Plan — Trip-Service Guaranteed Rewards + Pricing Rating-Based & Geo-Configured Pricing

## TL;DR (docs-only per [[trips-enjoy-platform-docs-template]])

Three features, two primary services, **~17 services** touched, **~60 files** across **5 phases**.

1. **trip-service** — per-trip + hourly/daily guaranteed rewards (configurable) for **driver AND user** anchored on trip completion via new `trip.reward.granted.v1` + `trip.reward.reversed.v1`.
2. **pricing-service (A)** — **rating-density surge-pressure** (low driver rating × dense trips in nearby zones → small multiplicative bump, composed with existing surge, capped by `max_multiplier`).
3. **pricing-service (B)** — **frequent-rider loyalty discount** (customer has ≥ N trips in zone in 30d → small negative line; AFTER promotion, BEFORE tax, capped at `min_fare`).
4. **pricing-service (C) + admin-service** — new **geo-config admin API in admin-service** (NOT configuration-service per user's choice) for per-location overrides + city-to-city OD-pair corridors; pricing consumes via new event `pricing.geo_config.updated.v1`.

Per [[trips-enjoy-platform-docs-template]], [[accounting-four-layer-truth-model]], [[trips-enjoy-services-with-accounting-impact-section]], [[user-prefers-comprehensive-cross-service-coverage]].

**Naming:** event payload `<domain.entity.event.vN>`; topic `<domain.entity.event>` (no `.vN`); kebab-case files; snake_case tables/columns; PascalCase logical entities; UUID refs across services (no FKs) — per `EVENT_ARCHITECTURE.md:43-50` + `DATABASE_ARCHITECTURE.md:63-67`.

## Open assumptions (please confirm at exit)

1. **User-side reward account name** — TBD pending Finance; suggestion `2100_customer_credit_liability` mirroring `2100_*` liability range.
2. **Reversal semantics** — separate `trip.reward.reversed.v1` with `reversal_of_event_id`; never UPDATE on `trip.trip_reward` ([[accounting-four-layer-truth-model]]).
3. **User reward kind default** — `wallet_credit`; alternative `loyalty_points` configurable per city.
4. **Surge-density composition** — multiplicative (`composed = max(1.0, base × (1 + pct))`), capped by `pricing.surge.max_multiplier`.
5. **Loyalty vs promotion ordering** — loyalty AFTER promotion, BEFORE tax; promotions can opt-out via their rules.
6. **Geo-config versioning** — immutable `pricing.rule_bindings` + parallel `pricing.rule_bindings_history` (parallels configuration-service versioning per `CONFIGURATION_ARCHITECTURE.md:188-197`); admin rollback = new version pointing at prior.
