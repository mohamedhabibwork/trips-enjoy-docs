# Extend payment-service to support all 46 gateways from Nafezly/payments

## Goal

Make the docs-only `payment-service` (under `docs/services/payment-service/`) support all **46 payment gateway classes** shipped by [`Nafezly/payments`](https://github.com/Nafezly/payments/tree/main/src/Classes), without losing PCI scope, without leaking provider semantics to the integration services, and without breaking the platform's per-service docs contract.

The current docs treat "the payment provider" as a single concept (4 named examples: Stripe, Adyen, Mada, HyperPay). The new model is a **gateway registry + per-gateway driver** — analogous to file-service's `StorageDriver` abstraction.

## Architectural design

### 1. Driver abstraction (mirrors file-service)

Add a `PaymentGatewayDriver` interface and a per-gateway driver package convention:

- **Interface surface** — `create`, `authorize`, `capture`, `void`, `refund`, `verify`, `getPayout`, `probe`, `shutdown` (modelled on file-service's `StorageDriver`). All gateway-specific HTTP, signing, and webhook parsing lives behind the driver.
- **One package per gateway** — `internal/payment/drivers/<gateway_id>/`. The service depends on the interface, not on any individual gateway. Adding a 47th gateway is a new package + a config row, not a code change elsewhere.
- **Driver resolution precedence** — `payment_intent.gateway_pin → tenant_override → region_default → currency_method_default → env_default`. Mirrors file-service §6.
- **Driver-agnostic payment_intent schema** — `gateway_id` (FK_ref to catalog) replaces the free-text `provider` column. Driver-specific state lives in JSONB (`gateway_locator`, `gateway_request_sanitised`, `gateway_response_sanitised`).
- **Per-gateway isolation** — per-gateway circuit breaker, bulkhead, retry, timeout (mirrors `SERVICE_ISOLATION.md` per-downstream rules). One bad gateway does not starve the others.
- **Per-gateway error mapping** — `payment_gateway_error_mapping` table translates gateway-native codes to platform codes (`PAYMENT_CARD_DECLINED`, `PAYMENT_INSUFFICIENT_FUNDS`, `PAYMENT_PROVIDER_UNAVAILABLE`). This is the row referenced by `DOWNSTREAM_ERROR_CATALOG.md` §5 L289–291.

### 2. Gateway registry (catalog table, mirrors `storage_drivers`)

New table `payment_gateways` (46 initial rows; closed list):

| Column | Purpose |
|---|---|
| `id` (TEXT PK) | e.g. `stripe`, `paypal`, `hyperpay`, `paymob`, `paymob_wallet`, `binance`, `perfect_money`, `volet`, `payeer`, `now_payments`, `now_payments_invoice`, `coin_payments`, `cryptomus`, `heleket`, `enot`, `changelly` (broken — disabled), `prime` (broken — disabled), `wise`, `payrexx`, `payop`, `bigpay`, `paycec`, `payermax`, `payzink`, `payzink_direct`, `totalpay`, `totalpay_direct`, `thawani`, `paylink`, `mamo`, `ziina`, `fawaterak`, `xpay`, `tap`, `kashier`, `paytabs`, `telr`, `clickpay`, `myfatoorah`, `opay`, `korapay`, `yallapay`, `paysky`, `fawry`, `paypal_credit` |
| `kind` | enum (`card`, `mena_wallet`, `mena_aggregator`, `crypto`, `e_currency`, `direct_card_3ds`, `payout`, `latam`, `apac`, `local_apm`) |
| `state` | `enabled` / `draining` / `disabled` |
| `priority` | int (lower wins) |
| `regions` | array — eligible regions |
| `supported_currencies` | array — ISO 4217 |
| `supported_methods` | array — `card`, `wallet`, `bnpl`, `bank_transfer`, `crypto` |
| `signature_scheme` | enum (`hmac_sha256`, `hmac_sha512`, `rsa_sha256`, `md5`, `sha256`, `paypal_sdk`, `none`) |
| `verify_style` | enum (`get_redirect`, `webhook_post`, `signed_webhook`, `cache_lookup`, `iframe_postback`) |
| `vault_path` | text — `secret/payment-service/gateway/<id>/<env>` |
| `health` / `health_last_checked_at` | synthetic probe results |
| `config_hash` | SHA-256 of resolved config (no-op duplicate reloads) |
| `metadata` | JSONB — gateway-specific extras (e.g. `thawani.amount_unit = "baisa"`, `binance.currency_hardcoded = "BUSD"`, `paymob.refund_uses_dd = true`) |
| `is_default` / `version` | standard |

Plus companion tables mirroring file-service:

- `payment_gateway_assignments` — per-intent source audit
- `payment_gateway_history` — pin / drain / migrate audit
- `payment_gateway_intent_registry` — `(gateway_id, gateway_intent_id)` uniqueness + replay-protection
- `payment_gateway_health_events` (partitioned monthly) — probe log
- `payment_gateway_error_mapping` — vendor-code → platform-code table

### 3. Existing schema impact

- Rename `provider` → `gateway_id` on `payment_intents`, `payment_attempts`, `payouts`, `webhook_events`. Each becomes a FK_ref (no DB FK) to `payment_gateways.id`. CHECK now enumerates the 46 gateway_ids.
- `provider_region` → `gateway_region` with FK_ref to a closed `regions` enum.
- `provider_token` stays (the platform's stored tokenised reference) but moves under a new `payment_methods` table owned by this service.
- `ReconciliationRun.provider_total` becomes JSONB keyed by `gateway_id` (per-gateway reconciliation runs are the new default).
- Adding a new gateway is a config-only change — no schema migration (mirrors file-service ERD §11 L782–787).

### 4. Configuration key family

New family `payment.gateway.*` in configuration-service (mirrors `trip.reward.*`):

```
payment.gateway.default                       — env default gateway_id
payment.gateway.<id>.enabled                   — bool
payment.gateway.<id>.priority                  — int
payment.gateway.<id>.regions                   — array
payment.gateway.<id>.supported_currencies      — array
payment.gateway.<id>.supported_methods         — array
payment.gateway.<id>.signature_scheme          — enum
payment.gateway.<id>.verify_style              — enum
payment.gateway.<id>.health_url                — probe URL
payment.gateway.<id>.webhook_ttl_seconds       — int
payment.gateway.override.tenant.<tenant_id>    — pin tenant → gateway
payment.gateway.override.region.<region>       — pin region → gateway
payment.gateway.override.currency.<iso4217>    — pin currency → gateway
payment.gateway.override.payment_method.<method> — pin method → gateway
```

### A. New file — `docs/services/payment-service/GATEWAYS.md`

| Column | Source |
|---|---|
| `gateway_id` | registry id |

| `status_string` | the success status convention to translate |
