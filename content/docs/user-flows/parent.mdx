Surface: a section of the traveler app (D-124). Role: parent or guardian (a traveler).

## Registration

A parent is a traveler ([Traveler App](/en/docs/user-flows/traveler), [UF-TRV-02](/en/docs/user-flows/traveler#uf-trv-02-register-and-verify)). No extra registration. Linking a child needs the booking reference, the child's name as on the booking, and a guardianship declaration recorded as consent.

## Eligibility (instead of approval)

| Condition | Required |
|---|---|
| Parent's plan | Explorer or VIP |
| Organization's plan | Growth or Enterprise |
| Trip setting | Child tracking switched on |
| Live position | Only while the trip is In Progress |

All three plan and setting conditions must hold ([OD-05](/en/docs/brd/compliance#11-open-decisions), proposed). The blocked screen says which one fails; only the parent-plan case offers an upgrade.

## Flows

### UF-PAR-01. Link a child
<Steps>
<Step>
Parent tracker, Add child.
</Step>
<Step>
Enter booking reference and the child's name; confirm the guardianship declaration.
</Step>
<Step>
Linked: the child appears with the trip. Refused: generic message (invalid reference, name mismatch, not a child passenger, or tracking off for the trip).
</Step>
</Steps>
Rules: [FR-PAR-01](/en/docs/srs/requirements/par#fr-par-01--linking-a-child), [BRL-10](/en/docs/brd/requirements#7-business-rules).

```mermaid
flowchart TD
A[Add child] --> P{Parent on Explorer or VIP?}
P -->|No| U[Upgrade prompt]
P -->|Yes| B[Enter booking reference, child name, declaration]
B --> V{Valid reference and name match?}
V -->|No| E[Generic refusal]
V -->|Yes| O{Organization Growth or Enterprise and trip switch on?}
O -->|No| X[Tracking unavailable, no upgrade offered]
O -->|Yes| L[Child linked]
```

### UF-PAR-02. Child trip status
For each linked child: trip, vehicle, seat, check-in status, programs, schedule; moderator contact.
Rules: [FR-PAR-02](/en/docs/srs/requirements/par#fr-par-02--parent-view-scope).

### UF-PAR-03. Live map
While the trip is In Progress and eligible: the vehicle's position on a map, updated live; before start and after end, no position.
Rules: [FR-PAR-03](/en/docs/srs/requirements/par#fr-par-03--eligibility), [FR-TRK-04](/en/docs/srs/requirements/trk#fr-trk-04--per-trip-child-tracking-switch), [FR-TRK-06](/en/docs/srs/requirements/trk#fr-trk-06--end-of-tracking).

### UF-PAR-04. Notifications
Boarding confirmed, trip started, stop reached, trip ended; also "not boarded" when the vehicle departs without the child checked in (proposed).
Rules: [FR-PAR-04](/en/docs/srs/requirements/par#fr-par-04--parent-notifications).

### UF-PAR-05. Report a child-safety concern
Describe the concern; a case is created and routed to the escalation contact; status shown.
Rules: [FR-PAR-07](/en/docs/srs/requirements/par#fr-par-07--child-safety-reporting).

### UF-PAR-06. Link ends
When the booking is cancelled or refunded, the child disappears from the tracker and live data stops. Child trip history is kept 1 year.
Rules: [FR-PAR-06](/en/docs/srs/requirements/par#fr-par-06--link-ends-with-the-booking).
