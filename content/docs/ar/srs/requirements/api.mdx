## FR-API-01 — واجهة API العامة
تصل الجهات المنظِّمة والشركاء إلى الرحلات والحجوزات عبر واجهة API عامة ذات إصدارات وموثقة على docs.trips-enjoy.com، بمصادقة عبر مفاتيح API للجهة المنظِّمة محدودة النطاق بحسب الصلاحية، مع تحديد المعدل لكل مفتاح.
<ReqMeta priority="Could" source="BR-API-01" />
- Given مفتاح API ملغى، when يُستخدم، then يُرفض الطلب باعتباره غير مصادَق عليه.

## FR-API-02 — دورة حياة مفاتيح API
تدير الجهات المنظِّمة مفاتيح API الخاصة بها: إنشاء مفتاح بالنطاق المختار من مجموعة الصلاحيات، وسرد المفاتيح النشطة، وإلغاء أي مفتاح فورًا؛ ويُرفض المفتاح الملغى باعتباره غير مصادَق عليه عند استخدامه التالي.
<ReqMeta priority="Could" source="BR-API-01" />
- Given موظف لا يملك صلاحية API، when يفتح إدارة المفاتيح، then يُرفض.
- Given مفتاح ملغى، when يصل طلب خلال دقيقة واحدة من الإلغاء، then يُرفض باعتباره غير مصادَق عليه.

## FR-API-03 — نقاط نهاية القراءة للموارد
تعرض واجهة API العامة نقاط نهاية للقراءة لمجموعات الموارد المنشورة — الرحلات والحجوزات والتوفر على الأقل — وتعيد البيانات نفسها التي تراها الجهة المنظِّمة في لوحة المعلومات، محدودة النطاق بمستأجر الجهة الطالبة.
<ReqMeta priority="Could" source="BR-API-01" />
- Given مفتاح نطاقه القراءة فقط، when يطلب رحلات جهة منظِّمة أخرى، then تكون الاستجابة فارغة لذلك المستأجر، لا خطأ.
- Given رحلة في حالة Draft، when يُطلب عبر واجهة API، then لا تُعاد.

## FR-API-04 — اصطلاحات واجهة API
تتبع نقاط النهاية في واجهة API العامة اصطلاحات الواجهة: ترقيم الإصدارات في عنوان URL تحت /api/v1 مع حصر التغييرات الجذرية في إصدار رئيسي جديد، وترقيم صفحات بالمؤشر لنقاط النهاية القائمة، ومغلف أخطاء موحد يحمل رمزًا ثابتًا ورسالة ومعرفًا للطلب.
<ReqMeta priority="Must" source="BR-API-01" />
- Given تغيير جذري في حقل استجابة، when يُطلق، then يُطلق ضمن إصدار رئيسي جديد ويحافظ /api/v1 على شكله.
- Given حدوث خطأ، when يُفحص محتوى الاستجابة، then يحتوي المغلف على الرمز والرسالة ومعرف الطلب.

## FR-API-05 — نشر مواصفة OpenAPI
تنشر واجهة API العامة مواصفة OpenAPI 3.1 مولدة من الشيفرة على docs.trips-enjoy.com، وتُحدَّث مع كل نشر، بحيث يبني الشركاء على العقد لا على التنفيذ.
<ReqMeta priority="Should" source="BR-API-01" />
- Given تغيير منشور يعدل نقطة نهاية، when تُجلب المواصفة، then تعكس الشكل المنشور.

## FR-API-06 — سلوك تحديد المعدل
تحدّ واجهة API العامة من المعدل لكل مفتاح بحدود معلنة، وتعيد 429 مع ترويسة Retry-After عند تجاوز الحد، وتعرض ترويسات الحصة المتبقية في كل استجابة.
<ReqMeta priority="Should" source="BR-API-01" />
- Given مفتاح تجاوز حده، when يصل الطلب التالي، then تكون الاستجابة 429 ويحدد Retry-After مدة الانتظار.
- Given مفتاح أقل بكثير من حده، when ينجح أي طلب، then تكون ترويسات الحصة المتبقية موجودة.

## FR-API-07 — تماثل عقد webhook
تستخدم تسليمات webhook المغلف والتوقيع نفسيهما المعتمدين في عقد واجهة API العامة: معرف حدث، ونوع، ووقت حدوث، وتوقيع (COM-04)، بحيث يتحقق الشركاء من السطحين بتنفيذ واحد؛ ويتبع سلوك التسليم [FR-ORG-06](/ar/docs/srs/requirements/org#fr-org-06--نظام-crm-وwebhooks).
<ReqMeta priority="Must" source="BR-API-01; BR-ORG-06" />
- Given webhook بسرٍّ مُدوَّر خلال فترة التداخل البالغة 24 ساعة، when يُفحص التوقيع بأي من السرين، then ينجح التحقق.
